## 为什么是这一步而不是「写工具」

原假设是「`ov` 是 shell 脚本、离模型太远、所以零八不用」。零八自己否掉了：

> 「10-20 我写了 2 条，是因为 456 明确说『写进记忆库』。**有人要求，我会写；没人要求，我不会想起来。
> 真正的变量是任务流里有没有『写记忆』这一步，不是工具在 bash 里还是在 JS 里。**
> 工具变原生能降低摩擦，但如果没有触发，摩擦低到零我也不会做。」

**关键观察**：零八的 `AGENTS.md` 里早就有「使用纪律：值得留下的事要及时 `ov note`」（2026-09-23 就写了）。
纪律不是缺的，**触发是缺的**。所以第 1 步不是写代码，是往手册里加一个能自动执行的收尾动作。

## 改了什么

在 `AGENTS.md` 的「我的长期记忆（OpenViking）」小节末尾（原「使用纪律」四条之后）
新增 `### 任务收尾三问`：

```
每次任务做完、准备回话之前，先自问三句：
1. 这次踩到坑了吗？     有根因、有排障路径的 → ov note（最高优先级）
2. 有什么变了？         项目状态 / 未了的事 / 在等谁 / 卡在哪 → ov note

三问全是「没有」→ 不写（不制造流水账）
任何一条「有」→ 当场写，别攒到「以后一起写」
```

配套三条边界：不记日常流水/工具原始输出/情绪与人物评价；写完不专门汇报「我记了记忆」；
这条不是可选项（引用了它自己 9-26 写过的「记忆这种事不能靠自觉」）。

## ★ 关键防护：备份绝不能留在 dshhome

`docs/engine-freeze.md` 记过一个雷：chokidar 启动时监视 `dshhome`，
遇到非 app 属主的文件会 `EACCES` → **整个引擎进程崩溃**。

所以备份必须放 `/data/local/tmp/`，改完必须 `chown u0_a284:u0_a284`，
并且用 `find <dshhome> -not -user u0_a284` 确认干净。
